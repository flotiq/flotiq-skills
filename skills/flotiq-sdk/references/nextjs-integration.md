# Next.js integration

## What a wired project has

`npx flotiq-nextjs-setup` (or a starter) leaves these; find them before writing anything, and don't run the setup again over them ([`sdk-setup.md`](sdk-setup.md)):

| What | Typical path | Purpose |
|---|---|---|
| Shared client | `src/lib/flotiq-api-client.ts` or `src/flotiq-api-client.ts` | The one `Flotiq` instance, with `@flotiq/nextjs-addon` middleware. |
| Draft route | `src/app/api/flotiq/draft/route.ts` | Toggles Next.js draft mode, guarded by `FLOTIQ_CLIENT_AUTH_KEY`. |
| Revalidate route | `src/app/api/flotiq/revalidate/route.ts` | Webhook target: `revalidateTag("flotiq-content", …)`. |
| Images | `next.config.*` | `images.remotePatterns` for `https://api.flotiq.com/image/**`. |
| Env | `.env.example` | `FLOTIQ_API_KEY`, `FLOTIQ_CLIENT_AUTH_KEY`. |

## The addon's middleware

`createNextMiddleware()` from `@flotiq/nextjs-addon`, passed to the client, does the Next.js-specific work, so fetch code stays plain SDK calls:

```ts
import { Flotiq } from "@flotiq/flotiq-api-sdk";
import { createNextMiddleware } from "@flotiq/nextjs-addon";

export const flotiqApiClient = new Flotiq({
  apiKey: process.env.FLOTIQ_API_KEY,
  middleware: [createNextMiddleware()], // { revalidateTime } to change the default
});
```

* tags every request with `flotiq-content` and `flotiq-content-<ctdApiName>` (the latter for targeted `revalidateTag`),
* sets `next.revalidate` (1 day by default),
* in draft mode sends `x-mode: preview` (drafts included), otherwise `x-visibility: public` (published only), so fetch code never branches on draft state,
* uses `cache: "no-store"` in development, in draft mode, and for write requests.

### With Cache Components

With `cacheComponents: true` (the default of `create-next-app` 16.4+), caching moves from fetch options (the middleware's `next: { revalidate, tags }`) to `"use cache"` functions, and an uncached Flotiq read outside `<Suspense>` fails the build ("uncached or runtime data during prerendering"). Put Flotiq reads in `"use cache"` functions with the same tags, so the revalidate route keeps working:

```ts
import { cacheLife, cacheTag } from "next/cache";

export async function getPosts() {
  "use cache";
  cacheTag("flotiq-content", "flotiq-content-blog_post");
  cacheLife("days");
  return (await flotiqApiClient.content.blog_post.list({ hydrate: 1 })).data;
}
```

Dynamic routes also need `generateStaticParams` (or a `<Suspense>` around the read). Draft mode bypasses `"use cache"`, so drafts still come fresh. Turning `cacheComponents` off instead keeps the middleware's caching as described above — choose one, deliberately.

## RSC fetch pattern

In Next.js 15+ `params` is a `Promise`. `PageProps<"/route">` is a global type generated by `next typegen` (Next.js 15.5+); older apps type it by hand: `{ params: Promise<{ slug: string }> }`.

```tsx
// src/app/blog/[slug]/page.tsx
import { notFound } from "next/navigation";
import { flotiqApiClient } from "@/lib/flotiq-api-client";

export default async function BlogPostPage({ params }: PageProps<"/blog/[slug]">) {
  const { slug } = await params;
  const result = await flotiqApiClient.content.blog_post.list({
    limit: 1,
    hydrate: 1,
    filters: { slug: { type: "equals", filter: slug } },
  });
  const post = result.data[0]; // typed via the generated flotiq-api.d.ts
  if (!post) notFound();
  // render post…
}
```

Generated types augment the `@flotiq/flotiq-api-sdk` module: `import type { BlogPost } from "@flotiq/flotiq-api-sdk"`. Media: `flotiqApiClient.helpers.getMediaUrl(media, { width, height })` with `next/image`.

## Draft mode

```
https://<host>/api/flotiq/draft?key=<FLOTIQ_CLIENT_AUTH_KEY>&redirect=/blog/my-post
```

`FLOTIQ_CLIENT_AUTH_KEY` is the app's own random secret. To open drafts from the Flotiq panel, put the same value in the space's [Content Preview settings](https://flotiq.com/docs/panel/SpaceSettings/content-preview/) as the Client Authorisation Key, with a route template per content type (`/{slug}`, `/blog/{slug}`). Keep the route as generated.

## Revalidation

So that edits show up at once, the space needs a webhook (Flotiq panel → Webhooks), one per production site:

* URL `https://<production-host>/api/flotiq/revalidate`, method `POST`, header `x-editor-key: <FLOTIQ_CLIENT_AUTH_KEY>` — the value production has.
* Triggered on create, update and delete of the space's content types. It doesn't cover `_media`: replacing an image file doesn't refresh the cache until an object that uses it changes. A content type added later has to be added to the webhook too.
* Until production has `FLOTIQ_CLIENT_AUTH_KEY`, the calls answer `401`, and edits show up only when the cache expires.

The webhook points at production only, so preview deploys shouldn't cache Flotiq responses (`createNextMiddleware({ revalidateTime: 0 })` there).

Regenerate `flotiq-api.d.ts` (`flotiq-typegen`) before trusting the shapes used in fetch code.
